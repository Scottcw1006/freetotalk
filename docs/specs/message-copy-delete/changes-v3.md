# 這一輪改了什麼

處理收件匣兩筆，都是別份規格的使用者裁決要本規格改字面：`message-store-normalization` 把訊息改成資料庫裡自己的一列、刪除狀態改成欄位，本規格綁舊儲存形式的四處要改；`message-like` 在對方訊息的長按選單加了「讚」，本規格「選單恰好兩項」要改。

**只改字面：沒有任何一條行為規則的實質改變，沒有產品程式碼的改動。** 現行規格入口：`v3/spec.md`（檔案沒有拆分，仍是 `spec.md`、`spec-decisions.md`、`spec-appendix.md` 三份）。`v2/` 沒有動；`v2` 裡本來就沒有 `test-cases.md`／`test-report.md`。`spec-decisions.md` 與 v2 逐位元組相同（本次沒有需要決策的事項）。
