# 這份文件怎麼讀

這是「長按訊息：複製、刪除與復原」的功能規格。聊天畫面上長按一則訊息會出現選單，可以把整則文字複製走，或把那一則刪掉；刪掉的訊息原地變成「已刪除的對話（復原）」，隨時可以復原。已刪除（未復原）的訊息在 App 的其他地方一律當作不存在：不送給模型、搜不到、不當標題、不當預覽。

- **只想知道這是什麼** → 讀「功能總覽」。
- **QA 要寫測試／冷讀驗收** → 讀「行為規格」與「任務與驗收標準」。行為規格不談實作手段。

- **現在還欠誰一個決定** → `spec-decisions.md`（**目前沒有待決事項**）。
- **為什麼長這樣、與別份規格哪裡對不起來** → `spec-appendix.md`。

**別的文件要指向本規格時**，寫 `docs/specs/message-copy-delete/<檔名> §節號「節名」`，不寫版號目錄；讀的人自己挑版號最大的目錄。

# 功能總覽

## 使用者看到什麼

在聊天畫面上**長按任何一則已經寫完的訊息**（你說的、對方說的、開場白、被中斷的回覆、「出錯了：…」都算），會跳出一個只有兩項的選單：「複製」「刪除」。

- **複製**：那一則的文字整則進剪貼簿 —— 超過一個螢幕也是整則，結尾的中斷標記（例如「…（已停止）」）也在裡面。
- **刪除**：不再問一次，那一則原地變成一個佔位「已刪除的對話（復原）」，位置與左右都不變，看不到原文。點「復原」，原文一字不差地回來。佔位永久保留：切到別段再回來、關掉 App 重開，它都還在，都還能復原。

兩種東西長按沒有反應：**正在一個字一個字生成中的那一則**（含還只有三個點的時候），以及**佔位本身**。對方還在生成時，別的訊息照常可以長按。

刪掉的訊息在別的地方就像不存在：下一次說話時**對方看不到它**；**搜尋搜不到它**；歷史清單的**標題**改取下一則沒被刪的「你說的話」，**預覽**改取最後一則沒被刪的訊息。復原之後，這些全部回到原樣。

刪除與復原都算這段對話的內容改變，它的**最後更新時間會前進**（在歷史清單與搜尋結果裡往上排）。複製不算。

## 系統被切成哪幾塊

| 這一塊 | 負責回答什麼問題 |
|---|---|
| **訊息的刪除狀態** | 每一則訊息現在算不算數。它是對話內容的一部分：跟著對話一起存、一起讀回來 |
| **「當作不存在」的純邏輯** | 給一段對話：標題是什麼、預覽是什麼、它算不算空白、哪幾則送給模型、哪幾則參與搜尋、兩個版本的內容算不算相同、某一則訊息此刻能做哪些動作。不依賴 Android，可被 JVM 測試直接呼叫 |
| **聊天狀態** | 接到「刪除這一則／復原這一則」時改變狀態、讓時間前進、當下存檔 |
| **聊天畫面** | 長按偵測、選單、把文字放進剪貼簿、畫佔位與「復原」 |
| **對話存取層** | 把刪除狀態連同原文存下來、讀回來；升級之後既有的對話照樣讀得回來 |

## 資料怎麼從一塊流到另一塊

```
長按一則訊息 → 畫面問純邏輯「這一則能做什麼」→ 有動作才出選單
  ├─ 複製 → 畫面把那一則的文字放進系統剪貼簿（不經過聊天狀態，不改任何資料）
  └─ 刪除 → 聊天狀態把那一則標成已刪除 → 時間前進 → 當下存檔
                → 狀態送出去：畫面畫佔位；搜尋、標題、預覽照純邏輯重算
點「復原」 → 聊天狀態把標記拿掉 → 時間前進 → 當下存檔 → 全部回到原樣
送出下一句 → 聊天狀態向純邏輯要「送給模型的上下文」→ 已刪除的不在裡面
```

## 這次會踩到的既有事實

每一條都寫了它為什麼影響這次要做的事。系統層級的描述在 `plan/architecture.html`，這裡不重複。

1. **中斷標記是訊息文字的一部分，不是畫面另外畫上去的。** 「…（已停止）」「…（已達長度上限）」「…（模型卡在重複迴圈，已中斷）」都是在回覆結束時直接接在那則訊息的文字後面存下來的；「出錯了：…」與「（這次沒有產生回覆，再說一次試試）」則是整則訊息的文字。→ 「複製含中斷標記」（§2.2）與「復原後標記還在」（§3.3）只要處理的是那一則的文字就自然成立；反過來，任何「先把標記拆掉再處理」的做法會打破它。
2. **助理訊息在畫面上是排版過的，原始字串與畫面上的字不一樣。** `**粗體**` 的星號不顯示；`- ` 或 `* ` 開頭的行顯示成「•」；`1)` 顯示成「1.」；段落之間的空行不顯示成空行。使用者的訊息怎麼打就怎麼顯示。→ 「複製泡泡的文字」對助理訊息有兩種可能的結果；§2.1 規定的是原始字串，所以複製出來的字與畫面上的字**不一定相同**，驗收要拿儲存裡的文字比，不是拿畫面比。
3. **「內容有沒有改變」的現行判斷只比訊息的 id 與文字。** 時間只在這個判斷回答「有改變」時前進。→ 只改刪除狀態而不動文字時，現行判斷會回答「沒改變」，時間不會前進，違反 §5.1。
4. **現行存檔時機只有三種：回覆收尾、按停止、切走。** 在畫面上改了對話卻不屬於這三種的動作，今天不存在。→ 刪除之後直接關掉 App，刪除狀態會不見，違反 §6.1。
5. **「空白對話」＝沒有任何一則「你說的話」；存一段空白對話等於把它從儲存裡移除**（`docs/specs/conversation-search/spec.md` §9.1「儲存一段空白對話等於刪檔，不是寫檔」、`docs/specs/conversation-store-db/spec.md` §1.2「一句話都沒說過的對話不留在儲存裡」）。→ 若把「已刪除」實作成「這一則不算訊息」，使用者刪光自己說的話之後一切走，**整段對話（連同所有佔位與原文）會從手機上消失**，違反 §4.5 與 §6.2。
6. **一段對話在資料庫裡是一列，所有訊息打包成那一列裡的一段 JSON 文字；資料庫設定成「結構版本對不上又沒有對應的搬遷時，整個清掉重來並提示一次」**（`docs/specs/conversation-store-db/spec.md` §5.1「儲存整份讀不起來時，告知一次後重新開始」）。→ 兩件事：(a) 每則訊息多記一個狀態，**不一定需要改動表格結構**；(b) 若改了結構版本而沒有提供搬遷，**升級的使用者會失去全部對話並看到「之前的對話紀錄讀不出來…」**，違反 §6.4。另外，訊息 JSON 的現行讀法遇到**缺少的欄位**若有預設值讀得起來，遇到**不認得的欄位**則整段讀不起來（那一段會從清單上消失，其餘不受影響）。
7. **資料庫層沒有自動化測試，產品程式碼也不加測試專用入口**（`conversation-store-db` 的 D1、D2 裁決）。→ 本輪的自動化測試一樣只測不開資料庫的純邏輯；裝置上要看儲存內容時，照 `docs/specs/conversation-store-db/spec-tasks.md`「測資與讀取的約定」：App 停止時唯讀地讀資料庫檔。**刪除狀態存在哪裡、長什麼樣，QA 要從架構文件查得到**（任務 6 驗收 4）。
8. **送給模型的上下文，現行規則是「這段對話到目前為止的每一則，但開頭連續的助理訊息不送」**（開場白是佈景，不是對白）；Gemma 的格式會把人格設定併進上下文的第一則。→ 拿掉已刪除的訊息之後，剩下的第一則可能變成助理訊息（使用者刪了自己的第一句、留著對方的回覆）；那時人格設定會被併進一則助理訊息裡。§4.1 因此規定「先拿掉已刪除的，再略過開頭的助理訊息」。
9. **搜尋結果是狀態送出去的路上當場算的，搜尋畫面與聊天畫面不會同時出現，點命中列只是打開那段對話、不會捲到那一則。** → 「命中的訊息後來被刪」這個情境在畫面上不可達：要刪就得先離開搜尋（查詢被清空），再進去時結果已經重算過。本規格不為它另立規則。
10. **模擬器上沒有讀寫剪貼簿的指令**（`docs/qa-environment.md`「剪貼簿」一節）。走得通的是 UI 路：到一個會原樣保留內容的輸入欄位長按 → 貼上 → 逐碼位讀回。聊天輸入框（提示文字「說點什麼…」）在送出之前不加工內容，可以當這個欄位。→ §2 在裝置上的判讀方式寫在任務 2。
11. **在模擬器上，一次生成通常只有數秒。** → 需要「在生成途中做某個動作」的條文可能攔不到；現場提示見 `docs/specs/conversation-store-db/spec-tasks.md`「攔住還在生成中的回覆：現場提示」。所以 §1.3、§1.4 另有不經過畫面的驗收（任務 1 驗收 7）。

# 行為規格

QA 主要照這一節寫測試。**用語**：
- **已完成的訊息**：不是正在生成中的訊息。不論它怎麼結束（正常、長度上限、重複迴圈、按停止、出錯）。
- **佔位**：一則已刪除、尚未復原的訊息在聊天畫面上的樣子。
- **已刪除**：一律指「已刪除且尚未復原」。
- **逐碼位相同**：兩個字串的每一個 Unicode 碼位、順序、數量都相同，含空白與換行。
- **測資保留字**：測資的訊息文字**不得含「已刪除」「復原」**這兩個詞（§4.2 要用它們當保證無命中的查詢）。

## §1 長按選單

**§1.1 長按一則已完成的訊息，出現一個選單，上面恰好兩項：「複製」「刪除」。** 點其中一項就執行並關閉選單。
- 守：任務 2 驗收 1。

**§1.2 可以長按的範圍：除了 §1.3 與 §1.5 兩種例外，聊天畫面上每一則訊息都可以。** 明確包含：你說的話、對方的回覆、每段對話開頭的開場白、結尾帶中斷標記的回覆、「出錯了：…」、「（這次沒有產生回覆，再說一次試試）」。整個泡泡都是長按範圍；泡泡比一個螢幕高時，長按看得到的任何一處都算。
- 為什麼不再分：使用者裁決只開了一個例外（生成中）。再替開場白或錯誤泡泡另開例外，使用者會遇到「這一則為什麼不能複製」而畫面上沒有任何線索。
- 守：任務 2 驗收 1（逐種類列舉）；任務 1 驗收 7。

**§1.3 正在生成中的那一則，長按沒有任何反應。** 從它出現（三個點的等待動畫）到它結束為止，長按它不出選單、不選取文字、不改變任何東西。**它一結束（不論怎麼結束）就變成已完成的訊息，立刻可以長按。**
- 守：任務 1 驗收 7（不經過畫面）；任務 2 驗收 2（裝置上，攔得到才判前半）。

**§1.4 對方還在生成時，別的已完成訊息照常可以長按、複製、刪除、復原。** 這些動作不得打斷生成：那則回覆繼續一個字一個字出現，結束時的文字與沒做這些動作時的規則相同（`docs/specs/stop-generation/spec.md` R8「兩種自動中斷維持現狀」等照舊）。
- 生成開始之後才刪除的訊息，**不影響這一次已經在生成的回覆**（上下文在送出那一刻就定了）；它從下一次送出起不算數（§4.1）。
- 守：任務 1 驗收 7（「別則可以」的判斷）；任務 3 驗收 7（裝置上，攔得到才判）。

**§1.5 佔位長按沒有任何反應。** 佔位上唯一能做的事是點「復原」。
- 守：任務 1 驗收 7；任務 3 驗收 2。

**§1.6 關掉選單不改變任何東西。** 選單出現後點選單以外的地方、或按系統返回鍵 → 選單消失，**仍停在聊天畫面（返回鍵這一下不得退出 App）**，訊息、剪貼簿、儲存的內容、最後更新時間都不變。
- 守：任務 2 驗收 3。

## §2 複製

**§2.1 點「複製」之後，系統剪貼簿裡是那一則訊息的整則文字（純文字），選單關閉。** 剪貼簿原本的內容被取代。
- **你說的話**：與那一則訊息的文字逐碼位相同（也就是與畫面上看到的相同）。
- **對方說的話（含開場白）**：與那一則訊息的**原始字串**逐碼位相同 —— 也就是存在手機上、搜尋拿去比對的那一份文字。畫面上因為排版而看不到的記號（`**`、行首的 `- `、`* `、`1)`、段落之間的空行）**都在複製出來的文字裡**。（使用者裁決。）
  - 可判定：一則對方的訊息原始字串是 `**重點**：` 換行 `- 蘋果` 換行、空一行、`1) 香蕉` → 複製出來的與這一串逐碼位相同；不是畫面上的「重點：」「• 蘋果」「1. 香蕉」。
  - 使用者知情接受的代價：貼到不認得這些記號的地方會看到星號與減號。
- 守：任務 1 驗收 10（不經過畫面）；任務 2 驗收 4（你說的話）、驗收 5（對方說的話）。

**§2.2 結尾的中斷標記一起複製。** 以「…（已停止）」「…（已達長度上限）」「…（模型卡在重複迴圈，已中斷）」結尾的回覆，複製出來的文字也以同一串標記結尾，標記前後不多不少任何字元。「出錯了：…」與「（這次沒有產生回覆，再說一次試試）」整則照樣複製得出來。
- 標記的字串由 `docs/specs/stop-generation/spec.md` R2「留下的是「按下停止那一刻畫面上的文字」+ 一個固定的中斷標記」與 R8 定義，本規格只引用。
- 守：任務 2 驗收 6。

**§2.3 超過一個螢幕的訊息也是整則。** 複製的範圍是那一則訊息的全部文字，與它此刻有多少顯示在螢幕上無關。
- 守：任務 2 驗收 7。

**§2.4 複製不改變任何資料。** 複製前後，那段對話的訊息、刪除狀態、儲存的內容、最後更新時間都相同；不觸發生成。
- 守：任務 2 驗收 8。

## §3 刪除、佔位與復原

**§3.1 點「刪除」之後，那一則訊息立刻原地變成佔位，不再詢問。** 沒有確認對話框、沒有倒數。其他訊息不受影響。
- 為什麼不問：隨時可以復原，再問一次只是多一步；與歷史清單刪對話「不會再問一次」一致。
- 守：任務 3 驗收 1。

**§3.2 佔位的樣子。**
- 顯示的字是「已刪除的對話（復原）」（全形括號），其中「復原」是可以點的。
- **位置不變**：佔位留在那一則訊息原本的順序上，前後的訊息不動。
- **左右不變**：你說的話的佔位靠右，對方說的話的佔位靠左。
- **看不到原文**：佔位上、以及讀畫面的工具讀到的佔位內容裡，都沒有原文的任何一段。
- 佔位與一般泡泡在視覺上分得出來（不得長得像一則內容是「已刪除的對話（復原）」的普通訊息），顏色取自主題。怎麼分由 RD 決定。
- 守：任務 3 驗收 1、2。

**§3.3 點「復原」之後，那一則訊息原地回來，與刪除前一字不差。** 文字逐碼位相同（含結尾的中斷標記）、作者與左右相同、位置相同；對方的訊息照原本的方式排版。
- 守：任務 3 驗收 3；任務 1 驗收 8（不經過畫面）。

**§3.4 每一則各自獨立，可以反覆。** 同一段對話可以有任意多個佔位；復原其中一個不影響其他；同一則可以刪除、復原、再刪除，次數不限。**一段對話的每一則都被刪掉也可以** —— 畫面上全是佔位，輸入框照常可以說下一句。
- 守：任務 3 驗收 4。

## §4 已刪除的訊息在別處一律當作不存在

**§4.1 送給模型的上下文不含已刪除的訊息；復原之後從下一次送出起又算數。**
- 送出一句話時，送給模型的上下文是：這段對話在這一句之前的訊息，**先拿掉已刪除的**，**再略過開頭連續的助理訊息**，其餘照原順序。
- 可判定（次序為什麼要寫死）：訊息依序是〔開場白、你 U1（已刪除）、對方 A1、你 U2、對方 A2〕→ 上下文是〔U2、A2〕，**不是**〔A1、U2、A2〕。違反時使用者會遇到：人格設定被併進一則對方的話裡（「這次會踩到的既有事實」第 8 條），對方的口吻跑掉。
- 可判定（復原）：同一組訊息把 U1 復原 → 上下文是〔U1、A1、U2、A2〕。
- 可判定（全刪）：這一句之前的訊息全部已刪除 → 上下文是空的，照常送得出去、得到回覆。
- 已刪除的訊息**只是不送**：它的原文不因為送出下一句而被改動或移除。
- 守：任務 1 驗收 5。**裝置上不判「模型是否真的沒看到」** —— 模型的回答不可預測，從回答推不出上下文；這條的權威在不經過畫面的測試。

**§4.2 搜尋搜不到已刪除的訊息；復原之後又搜得到。**
- 已刪除的訊息不產生命中列，不計入「N 段對話・M 則訊息」，不計入「還有 N 則符合」。一段對話唯一的命中都在已刪除的訊息裡時，那段對話不出現在結果裡。
- **佔位上的字不是訊息文字**：查「已刪除」或「復原」，不得因為畫面上有佔位而命中。
- 可判定（正向對照不得省略）：一段對話含 U1「apple kiwi」、A1「banana kiwi」，刪除 U1 → 查「apple」無命中；查「kiwi」恰好一則命中（A1），摘要是「1 段對話・1 則訊息」；查「已刪除」無命中。復原 U1 → 查「apple」命中 U1；查「kiwi」兩則。
- 開著的那段與歷史裡的每一段都適用；冷啟動之後也適用（刪除狀態是存下來的，§6.2）。
- 守：任務 1 驗收 4；任務 3 驗收 6（裝置上）。

**§4.3 歷史清單的標題取第一則沒被刪的「你說的話」。** 截短與省略號的規則照舊（`docs/specs/conversation-search/spec.md` §5.2「抽屜必須有下面這些東西，行為如下」）。
- 可判定：你說過「first」「second」，刪除「first」→ 標題是「second」；復原 → 標題回到「first」。
- **「你說的話」全部已刪除時，標題是「（訊息已刪除）」**（全形括號，共 7 個字元；使用者裁決）。復原任何一則「你說的話」之後，標題回到第一則沒被刪的那一句。
- 反方向不變：**從來沒說過話**的對話，標題仍是「還沒說話」。兩個標題不得混用 —— 「還沒說話」對一段說過話的對話不是真的。
- 守：任務 1 驗收 1；任務 3 驗收 5（裝置上）。

**§4.4 歷史清單的預覽取最後一則沒被刪的訊息（不分作者）。** 每一則都已刪除時，預覽是空的（那一行沒有字）。截短規則照舊。
- 可判定：最後兩則是你「question」、對方「answer」，刪除「answer」→ 預覽是「question」；再刪除其餘每一則 → 預覽是空的；復原「answer」→ 預覽是「answer」。
- 守：任務 1 驗收 2；任務 3 驗收 5（裝置上）。

**§4.5 「你說的話」全部被刪掉的對話，仍然是一段有內容的對話。** 它照常被存下來、留在歷史清單上、冷啟動之後還在、打得開、每一個佔位都還能復原。**「當作不存在」不延伸到「這段對話算不算空白」**：判斷空白時，已刪除的「你說的話」照樣算數。
- 為什麼：使用者裁決「佔位永久保留、可隨時復原、原文一直留在手機上」。若刪光自己的話會讓對話變成空白，切走的那一刻整段對話連同所有原文會從手機上消失（「這次會踩到的既有事實」第 5 條），而且沒有任何提示。
- 反方向不變：**從來沒說過話的對話仍然是空白對話**，不會因為本功能而被存下來（§6.5）。
- 守：任務 1 驗收 3；任務 4 驗收 3（裝置上）。

## §5 最後更新時間

**§5.1 刪除一則訊息、復原一則訊息，各讓那段對話的最後更新時間前進到動作當下。** 效果與其他內容改變相同：那段對話在歷史清單與搜尋結果裡排到最前，時間文字跟著變。
- 這是 `docs/specs/conversation-search/spec.md` §8.1「定義」那條「時間跟著內容走」的延伸：訊息算不算數，是內容的一部分。
- 守：任務 1 驗收 6（不經過畫面：只差刪除狀態的兩個版本，「內容有沒有改變」必須回答「有」）；任務 3 驗收 8（裝置上，讀儲存裡的時間）。

**§5.2 長按、選單出現、關掉選單、複製，都不讓時間前進。**
- 守：任務 2 驗收 3、8。

## §6 保存

**§6.1 刪除與復原當下就存下來。** 刪除（或復原）一則訊息之後，**不做任何其他動作**直接結束 App 的行程再冷啟動 → 那一則仍是佔位（或仍是復原後的樣子），那段對話的最後更新時間是動作當下那個值。
- 適用於已經有「你說的話」的對話。從來沒說過話的對話見 §6.5。
- 對方還在生成時做的刪除也適用本條；**那一刻被結束行程時，生成到一半的那則回覆留下什麼，本規格不定義**（見「明確不做」）。
- 守：任務 4 驗收 1。

**§6.2 刪除狀態與原文都留在手機上，沒有期限。** 切到別段再切回來、冷啟動、隔任意久之後：佔位還在原位，點「復原」得到的文字與刪除前逐碼位相同。已刪除的訊息在冷啟動之後仍然搜不到、不當標題、不當預覽、不送給模型。
- 從歷史清單刪掉整段對話時，它的已刪除訊息與原文跟著一起真的刪掉（`docs/specs/conversation-search/spec.md` §9.4「使用者從歷史清單刪掉一段對話，就是真的刪掉」照舊）。
- 守：任務 4 驗收 2；任務 1 驗收 8。

**§6.3 讀回來的刪除狀態，就是存進去的。** 一段對話存下再讀回來，每一則訊息的刪除狀態與存進去時相同，其餘欄位的要求照 `docs/specs/conversation-store-db/spec.md` §1.1「讀回來的，就是存進去的」。
- 守：任務 1 驗收 8。

**§6.4 升級到本版之後，手機上既有的對話全部保留。**（使用者裁決。）從本版之前的建置覆蓋安裝上來、第一次打開：既有的每一段對話都在，每一則訊息都是未刪除、文字逐碼位相同；**不出現**「之前的對話紀錄讀不出來，已經清空，從這裡重新開始。」；續接到上次離開的那一段；之後的刪除與復原在這些對話上照常運作。
- 守：任務 1 驗收 8 的後半（不經過畫面：沒有刪除狀態紀錄的舊資料讀成未刪除）；任務 4 驗收 4（裝置上）。

**§6.5 從來沒說過話的對話，不因為本功能而被存下來。** 在一段只有開場白的對話裡刪除（或復原）開場白 → 畫面上照常變成佔位（或復原），但儲存裡不因此多出一段；切走之後這段對話照舊不留下。
- 守：任務 4 驗收 3 的反向對照。

**§6.6 存不下來時，表現與既有的存檔失敗相同**（`docs/specs/conversation-store-db/spec.md` §5.2「一次存檔寫不進去時」）：不閃退，畫面上的刪除／復原照樣生效，出現那條既有的提示。
- **本條沒有獨立驗收，知情留白**：刪除與復原走的是與其他存檔相同的那一條路，那條路的失敗表現由 `conversation-store-db` 的任務 5 守；在裝置上為這兩個動作各重造一次「空間不足」的成本高，而會壞的樣子（另開一條不經過那條路的存檔）在任務 4 驗收 1 的正常路徑上看不出來 —— 這個缺口只靠架構建議 §A.3 提醒。

# 架構決策

**全部是給 RD 的建議，QA 不驗。** 必須成立的東西都在行為規格與驗收標準裡。

**§A.1 「已刪除」建議做成訊息上的一個狀態，訊息本身留在對話的訊息清單裡；「當作不存在」由讀的那一方決定。** 理由：§4.5 與 §6.2 要求原文與位置都留著，而標題、預覽、搜尋、上下文要略過它、空白判斷卻不能略過它 —— 「略不略過」隨用途不同，集中在一處回答比較不容易漏掉一個用途。把已刪除的訊息搬到另一個清單也做得到，但順序與 id 的延續要自己顧。

**§A.2 訊息 id 的延續。** 下一則訊息的 id 現在由「清單裡最大的 id 加一」算出來。已刪除的訊息若不在那個清單裡，新訊息可能撞到已刪除訊息的 id，復原時畫面會出現兩則同 id 的訊息（清單以 id 當鍵，會閃退）。照 §A.1 做就沒有這個問題。

**§A.3 刪除與復原的存檔，建議走與其他存檔同一條路**（同一個失敗提示、同一個「空白對話不寫」的規則）。理由見 §6.5、§6.6。

**§A.4 刪除狀態建議記在每則訊息自己的資料裡，不改表格結構。** 理由見「這次會踩到的既有事實」第 6 條：不改結構就不會碰到「清掉重來」那條路，§6.4 幾乎不需要額外工作；既有資料缺這個欄位時讀成「未刪除」。若 RD 判斷需要改表格結構，那會是這個專案第一次寫資料庫搬遷，而資料庫層沒有自動化測試 —— **請先在 `pm-inbox.md` 留一筆**。

**§A.5 聊天清單捲到最新一則的時機現在是看「訊息有幾則」。** 刪除與復原若改變了那個數字，每刪一則畫面就會跳到最底。照 §A.1 做數字不變。這一條沒有寫成行為規格，是因為我不確定現行捲動在所有情況下的表現；RD 實作時若發現刪除會讓畫面跳走，請回報，我補成規則。

# 任務與驗收標準

**自動化測試一律是 JVM 測試、不開資料庫、不依賴 Android**（「這次會踩到的既有事實」第 7 條）。任務 1 的每一條驗收都要指得出對應的測試。

## 任務 1：「當作不存在」的純邏輯

- **說明**：讓「標題、預覽、空白判斷、搜尋、送給模型的上下文、內容有沒有改變、某一則能做哪些動作、存進去讀回來」這幾個問題，在有已刪除訊息時給出 §1、§3–§6 規定的答案，而且每一個都能被 JVM 測試直接呼叫。上下文的組成今天寫在聊天狀態裡、無法被測試直接呼叫 —— 這個任務要求它變成可以。
- **對應功能模組**：訊息的刪除狀態；「當作不存在」的純邏輯；對話存取層裡對話與儲存形式互轉的那一段。
- **驗收標準**：
  1. **標題（§4.3）**：有測試斷言 §4.3 的可判定案例（刪除「first」→「second」；復原 →「first」），外加：第一則「你說的話」已刪除、第二則超過截短上限 → 標題是第二則截短後的樣子（截短規則照舊套用）。再外加：「你說的話」全部已刪除（對方的訊息留著）→ 標題**恰好是**「（訊息已刪除）」；復原其中一則 → 標題是那一則；正向對照：只有開場白、從來沒說過話的對話 → 標題是「還沒說話」。
     - 獨自抓得到：只在畫面上過濾、標題仍取原本第一句的實作。
  2. **預覽（§4.4）**：有測試斷言 §4.4 的三個可判定案例（含「全部已刪除 → 空字串」）。
  3. **空白判斷（§4.5）**：有測試斷言：「你說的話」全部已刪除的對話**不是**空白、存檔時的處置是「寫入」；正向對照：只有開場白的對話、以及只有一則已刪除開場白的對話，**是**空白、處置是「移除」。
     - 獨自抓得到：把已刪除當成「這則不算訊息」的實作 —— 它會讓使用者的整段對話在切走時消失。拿掉「空白判斷照樣算已刪除的訊息」這個保護時，第一個案例必須變紅。
  4. **搜尋（§4.2）**：有測試斷言 §4.2 的可判定案例全部（刪除後「apple」無命中、「kiwi」恰好一則且兩個數字是 1 與 1、「已刪除」無命中；復原後「apple」命中、「kiwi」兩則），外加：一段對話有四則含「kiwi」的訊息、刪除其中一則 → 顯示三則、沒有「還有 N 則符合」的餘數（餘數為 0）。
     - 正向對照不得省略：只斷言「搜不到」，一個永遠回空的搜尋也會通過。
  5. **上下文（§4.1）**：有測試斷言 §4.1 的三個可判定案例（次序、復原、全刪），外加既有行為的對照：沒有任何已刪除訊息時，上下文是「這一句之前的每一則，略過開頭的助理訊息」。
     - 獨自抓得到：這是「對方看不看得到已刪除的訊息」唯一的驗收；裝置上判不出來。拿掉「先過濾再略過開頭」的次序時，第一個案例必須變紅。
  6. **內容有沒有改變（§5.1）**：有測試斷言：兩個版本的對話只差在某一則訊息的刪除狀態 → 判斷回答「有改變」；正向對照：兩個版本只差在「是否生成中」→ 回答「沒改變」（既有行為，不得碰壞）。
  7. **某一則能做哪些動作（§1.2–§1.5）**：有測試斷言：已完成的訊息（你說的、對方的、id 為 0 的開場白、文字以中斷標記結尾的、文字以「出錯了：」開頭的）→ 複製與刪除；生成中的訊息（文字為空、文字不為空各一）→ 沒有任何動作；已刪除的訊息 → 沒有長按動作；**同一段對話裡有一則生成中的訊息時，其餘已完成的訊息仍然是複製與刪除**。
     - 獨自抓得到：模擬器上生成只有數秒，§1.3、§1.4 在裝置上常常攔不到；這一條讓那兩條規則不依賴攔不攔得到。
  8. **存進去讀回來（§3.3、§6.2、§6.3）**：有測試斷言：一段含已刪除訊息的對話，轉成儲存形式再經由「依 id 取」與「取全部」共用的讀取規則轉回來 → 每一則的刪除狀態與文字都與原本相同。測資：已刪除的你說的話、已刪除且以「…（已停止）」結尾的回覆、未刪除的訊息各至少一則；文字含換行。
     - **舊資料（§6.4）**：一段以本版之前的形式存下的對話（沒有任何刪除狀態的紀錄）經由同一段讀取規則讀回來 → 讀得起來，每一則都是未刪除、文字相同。測資直接寫成本版之前的儲存形式（那個形式在 commit `e8cf9aa` 的原始碼裡查得到），不得用本版的程式產生。
       - 獨自抓得到：讀取端把刪除狀態當成必填、舊資料整段讀不起來的實作 —— 升級的使用者會看到歷史清單變空，而且沒有任何提示（讀不起來的一段只是靜靜被略過）。
  9. `./gradlew testDebugUnitTest` 全數通過，含本輪之前就存在的全部測試。
  10. **複製出來的文字（§2.1、§2.2）**：有測試斷言「某一則訊息複製出來的文字」：對方的訊息原始字串是 §2.1 可判定的那一串 → 結果與它逐碼位相同（`**`、`- `、`1)`、空行都在）；你說的話 `a*b*  **x**`（含連續空白）→ 相同；以「…（已停止）」結尾的回覆 → 結果以同一串標記結尾、與原始字串相同。
      - 獨自抓得到：複製時走了一次排版再取字的實作。裝置上要造出「原始字串與畫面不同」的回覆得靠模型配合（任務 2 驗收 5），這一條不靠。

## 任務 2：長按選單與複製

- **說明**：聊天畫面上的長按、選單、放進剪貼簿。
- **對應功能模組**：聊天畫面。
- **剪貼簿怎麼判讀（本任務通用）**：複製之後，到聊天輸入框（提示文字「說點什麼…」）長按 → 貼上，用讀畫面的工具逐碼位讀回輸入框的內容，再把輸入框清空，**不要送出**。不要看鍵盤上剪貼簿提示條的字（它會修剪空白）。每一條判讀之前先複製一段已知的別的文字，確認讀到的不是上一條留下的。
- **驗收標準**（在裝置上）：
  1. **選單（§1.1、§1.2）**：對下列每一種各長按一次，都出現恰好含「複製」「刪除」兩項的選單：你說的話、對方正常結束的回覆、開場白、以「…（已停止）」結尾的回覆。「出錯了：…」與「（這次沒有產生回覆…）」在裝置上造不出來時記「本環境無法執行」，由任務 1 驗收 7 守。
  2. **生成中（§1.3）**：送出一句會產生較長回覆的話，在回覆結束之前長按那則回覆 → 沒有選單、畫面沒有變化。**這一次算不算數**：長按之後那則回覆仍在變長才算；攔不到記「本環境無法觀察」並寫明試過什麼，不判 fail。**後半每次都判**：那則回覆結束之後長按它 → 出現選單。
     - 獨自抓得到（後半）：把「不能長按」綁在「這是最後一則助理訊息」而不是「生成中」的實作。
  3. **關掉選單（§1.6、§5.2）**：先讀儲存的內容當基準（照 `docs/specs/conversation-store-db/spec-tasks.md`「測資與讀取的約定」）。長按一則訊息 → 點選單以外的地方；再長按 → 按系統返回鍵。兩次之後：仍在聊天畫面、那一則仍是原樣；儲存的內容與基準相同（含最後更新時間）。
  4. **你說的話（§2.1）**：送出 `Copy  me: a*b*c  **x** - y`（中間有連續兩個空白）→ 複製它 → 讀回的內容與送出的逐碼位相同（星號、連續空白都在）。
     - 獨自抓得到：對所有訊息一律走排版再取字的實作；收合空白的實作。
  5. **對方說的話（§2.1）**：
     - (i) 開場白：複製目前人格的開場白 → 讀回的內容與畫面上那則開場白逐碼位相同。
     - (ii) 含記號的回覆：請模型用條列與粗體回答（提示由驗的人選，例如 `List three fruits as a bullet list and make one of them bold`），等回覆結束，複製它，讀回內容記為 C。App 停止後唯讀地讀儲存裡那一則的文字記為 S（怎麼讀照架構文件，任務 6 驗收 4）→ **C 與 S 逐碼位相同**。
     - **(ii) 這一次算不算數**：S 裡至少有一個畫面上看不到的記號（`**`、行首的 `- ` 或 `* `、`1)`、空行）才算；不含時換提示或換模型再試，試過仍造不出來記「本環境無法觀察」並寫明試過什麼，不判 fail（由任務 1 驗收 10 守）。
     - 獨自抓得到：剪貼簿這一段路上對文字的加工（任務 1 驗收 10 看不到放進剪貼簿之後的事）。
  6. **中斷標記（§2.2）**：造一則以「…（已停止）」結尾的回覆（照 `docs/specs/stop-generation/spec.md`「正確行為」的共同前置）→ 複製它 → 讀回的內容以「…（已停止）」結尾，標記之後沒有任何字元；App 停止後讀儲存裡那一則的文字，與讀回的內容逐碼位相同。
  7. **超過一個螢幕（§2.3）**：送出一則 3,000 個字元以上、開頭是 `BEGIN-`、結尾是 `-END` 的訊息（中間用不含空白的 ASCII 字元填充）。在它的開頭捲出螢幕的情況下長按看得到的部分 → 複製 → 讀回的內容以 `BEGIN-` 開頭、以 `-END` 結尾、長度與送出的相同。
  8. **複製不改資料（§2.4、§5.2）**：先讀儲存的內容當基準 → 複製任一則訊息 → 結束 App 行程再讀：與基準相同（含最後更新時間）；複製之後狀態列沒有變成「輸入中…」。

## 任務 3：刪除、佔位、復原與時間

- **說明**：刪除與復原這兩個動作在聊天畫面、搜尋、歷史清單上的表現，以及時間前進。
- **對應功能模組**：聊天狀態；聊天畫面。
- **驗收標準**（在裝置上）：
  1. **刪除（§3.1、§3.2）**：一段對話依序有開場白、你「first kiwi」、對方的回覆、你「second」、對方的回覆。長按「first kiwi」→ 刪除 → 沒有任何確認；原本的位置上是靠右的佔位，讀畫面的工具讀得到「已刪除的對話」與「復原」，**整個畫面上讀不到「first kiwi」**；其餘四則原樣。再刪除一則對方的回覆 → 它的佔位靠左。
  2. **佔位不能長按（§1.5）**：長按佔位（「復原」以外的位置）→ 沒有選單，佔位還在。
  3. **復原（§3.3）**：造一則以「…（已停止）」結尾的回覆，先記下它在畫面上的文字；刪除 → 點佔位上的「復原」→ 它回到原位、靠左、文字與記下的逐碼位相同（含標記）。
     - 獨自抓得到：刪除時把文字清掉、或復原時重新產生文字的實作。
  4. **各自獨立、可以反覆（§3.4）**：刪除三則（含開場白）→ 三個佔位；復原中間那一個 → 另外兩個仍是佔位；同一則再刪除、再復原一次，結果正確。把每一則都刪掉 → 輸入框仍可送出一句話並得到回覆。
  5. **標題與預覽（§4.3、§4.4）**：沿用驗收 1 的對話（不復原），再刪除最後一則對方的回覆；開一段新的對話，打開抽屜 → 那一列的標題是「second」、預覽是「second」。回到那段對話復原「first kiwi」，再切走 → 標題是「first kiwi」。
  6. **搜尋（§4.2）**：驗收 1 的狀態下（「first kiwi」已刪除）進入搜尋查「first」→ 那段對話不因為這一則而命中；查「已刪除」→ 顯示「找不到符合…」；正向對照：查「second」→ 命中。復原之後查「first」→ 命中。
  7. **生成中刪別則（§1.4）**：送出一句會產生較長回覆的話，回覆結束之前刪除更早的一則訊息 → 那一則變成佔位，回覆繼續變長直到自己結束。**算不算數**：刪除之後回覆仍在變長才算；攔不到記「本環境無法觀察」並寫明試過什麼，不判 fail（由任務 1 驗收 7 守）。
  8. **時間前進（§5.1）**：三段有內容的對話，最後更新時間由舊到新是 A、B、C，彼此至少隔 1 分鐘。打開 A（只是打開，不說話）→ 刪除 A 的一則訊息 → 記下時刻 t1 → 開一段新的對話 → 抽屜上 **A 排在 B、C 前面**；App 停止後讀儲存：A 的最後更新時間落在 t1 前後數秒內，B、C 的不變。等至少 1 分鐘，回到 A 復原那一則 → 記下 t2 → App 停止後讀儲存：A 的時間落在 t2 前後數秒內（**晚於**刪除那一次）。
     - 獨自抓得到：只在刪除時推進、復原時不推進的實作；以及「這次會踩到的既有事實」第 3 條那個現行判斷沒改的情形（兩次都不推進）。

## 任務 4：保存與升級

- **說明**：刪除狀態與原文的留存；升級之後既有的對話保留。
- **對應功能模組**：對話存取層；聊天狀態（存檔時機）。
- **驗收標準**（在裝置上）：
  1. **當下就存（§6.1）**：在一段已經有來有往的對話裡刪除一則訊息，**不做任何其他動作**，立刻 `adb shell am force-stop com.example.demo` 再打開 → 續接到那段對話，那一則是佔位。點「復原」，同樣立刻強制停止再打開 → 那一則是復原後的原文。
     - 獨自抓得到：刪除狀態只留在記憶體、等下一次切換或回覆收尾才順便存的實作（「這次會踩到的既有事實」第 4 條）。
  2. **一直都在（§6.2）**：刪除一則你說的話（文字記下來）與一則對方的回覆 → 切到另一段、再切回來 → 兩個佔位都在原位；冷啟動 → 仍在；此時搜那則你說的話裡的字 → 無命中。App 停止後唯讀地讀儲存：**那兩則的原文仍在儲存裡**（怎麼讀、刪除狀態記在哪裡，照架構文件，任務 6 驗收 4）。再打開 App 點「復原」→ 文字與記下的逐碼位相同。
     - QA 驗不到的：「沒有期限」只能驗到這一輪操作的時間跨度。
  3. **刪光自己的話（§4.5）與反向對照（§6.5）**：一段對話裡把每一則「你說的話」都刪掉（對方的留著）→ 開一段新的對話 → 抽屜上那一段**仍在**；冷啟動之後仍在，點開 → 佔位都在，逐一復原得到原文。**反向對照**：在一段只有開場白的新對話裡刪除開場白 → 開另一段新的對話 → 抽屜上**沒有**多出那一段；App 停止後讀儲存，對話段數沒有因為它而增加。
  4. **升級（§6.4）**：用本輪實作之前的程式（commit `e8cf9aa` 的原始碼）建置並安裝，建立至少兩段有來有往的對話（其中一段含以「…（已停止）」結尾的回覆），記下每一則的文字；覆蓋安裝本輪的建置（不清資料）→ 打開 → 不出現「之前的對話紀錄讀不出來…」；兩段都在抽屜或畫面上；每一則都不是佔位、文字與記下的相同；對其中一則刪除再復原，結果正確；冷啟動一次之後以上仍然成立。
     - 獨自抓得到：改了資料庫的結構版本而沒有搬遷的實作（全部對話被清掉並出現那句提示）—— 任務 1 驗收 8 不開資料庫，看不到這一種。
     - 前置提醒：APK 很大，模擬器的資料分割區要先有足夠空間放得下覆蓋安裝；空間不足造成安裝失敗時記「本環境無法執行」並寫明，不判 fail，也不得因此清資料重裝後判 pass。
