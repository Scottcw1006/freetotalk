- 測資形狀**完全符合**條文：起點案例是 `"😀"×15 + "測" + "北京" + "尾"×60`（命中起點索引 31、引子想從 11 開始，11 正好是第 6 對的後半）；尾端案例是 `"測"×30 + "北京" + "尾"×7 + "😀"×20`（命中起點 30、視窗想在 70 結束，69 正好是某一對的前半）。
- **兩個案例確實各自獨立**：我在沙箱複本上把 `avoidSplittingPairAt` 改成直接回傳原索引 → **只有**第一支變紅；改回來後把 `avoidSplittingPairBefore` 改成直接回傳原索引 → **只有**第二支變紅。條文這一項成立。
- **但兩支測試的斷言只有那個 surrogate 配對迴圈**，沒有任何一行斷言片段含有「北京」。一個回傳空片段（或只回傳省略號）的實作會讓兩支都通過 —— 條文自己點名的那個失效模式現在沒有被擋住。
- 這是**實作／測試沒有做到條文指名的東西**，不是規則要改。產品行為本身是對的（實機片段確實含查詢詞）。
