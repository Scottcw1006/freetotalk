### 決策 M：抽屜標題／預覽截短時，「一個字」以什麼為單位

（源自收件匣 [2026-09-16 01:10]「這是 bug：抽屜標題／預覽截短切開 emoji，已在實機重現」）

**問題**：截短是以 UTF-16 code unit 計算的。截點落在一個 emoji 的兩個 code unit 中間時，會留下半個字（已在實機重現，見 `docs/specs/drawer-cut-splits-emoji/findings.md`）。v3.19 已經把「不得留下半個 code point」寫進 `spec.md` §5.2「抽屜必須有下面這些東西，行為如下」，也開了任務 17。**還沒定的是更上面一層**：很多 emoji 由好幾個 code point 組成，但使用者看起來是一個字，例如帶膚色的 👍🏽、ZWJ 家庭 👨‍👩‍👧、國旗 🇹🇼、帶變體選擇符的 🌧️（v3.18 那則測資用的就是這個）。如果只保證不留半個 code point，這些字仍然可能從中間被切開。

**為什麼要你選**：兩個方向使用者看到的東西不一樣。其中一個方向會讓抽屜和搜尋片段對「切開」的定義不同：搜尋片段（`spec.md` §4.4「不得從 surrogate pair 中間切開」）也只保證 code point 這一層。

| 選項 | 使用者會看到 | 得到 | 代價 |
|---|---|---|---|
| **(a) 只保證不留半個 code point（與 §4.4 同一層）** | 不會再出現壞掉的方框或問號，讀畫面的工具也不會再崩潰。但組合 emoji 被切在中間時，會變成另一個看起來完整的樣子：👍🏽 變成 👍、家庭只剩第一個人、🌧️ 可能變成單色的 🌧。國旗只剩一半時**可能**顯示成方框字母，這點我沒有在實機確認 | 修掉已經重現的那個問題；不經過裝置的測試可以判得很精確；與搜尋片段同一個定義 | 組合 emoji 仍可能被切成「不是使用者打的那個字」，而且這一類沒有條文守 |
| **(b) 以使用者看到的一個字（grapheme cluster）為單位** | 「…」前面的最後一個字一定是使用者打的完整的字 | 抽屜上不會出現被切開的 emoji | 抽屜與搜尋片段對「切開」的定義不同，片段仍可能切開家庭 emoji。另外，怎麼切出一個字要靠 Unicode 的斷字資料，**我不確定不經過裝置的測試環境和手機對新 emoji 的斷字結果是否一致**，所以測試的可信度會打折，可能還要在裝置上補驗 |
| **(c) (b)，並把搜尋片段 §4.4 一起升級** | 抽屜和搜尋都不會切開任何一個字 | 兩處用同一個定義 | 會動到搜尋片段的視窗與標示區間（§4.2–§4.6 的位置都以 code unit 計），這是跟這個 bug 無關的改動，**修過頭的風險最高**。(b) 的測試可信度問題也同樣存在 |

**我傾向 (a)**，(b)、(c) 記進「明確不做」，並寫明觸發條件：有人回報抽屜或搜尋片段上的 emoji 被截成另一個樣子。理由是，已經重現的傷害是「壞掉的字，加上讀畫面的工具崩潰」，(a) 能完整修掉；組合 emoji 被截成另一個完整的字，嚴重程度不同，也還沒有人回報過。**不確定的地方**：如果國旗在手機上真的會顯示成壞掉的樣子，(a) 就沒有完全修掉「壞掉的字」。這點不在裝置上看我無法確認。

**拍板前 RD 能不能動**：任務 17 的驗收 1–5 在三個選項下都成立，因為 (b)、(c) 都包含 (a)，**所以可以先開工**；驗收 6（組合 emoji）要等拍板。這是我自己的判斷，你也可以要求整個任務 17 等拍板，代價是那個崩潰會多留一輪。

**拍板後由我做的事**：選 (a)，就把 §5.2 那一項的「待決策 M」拿掉、組合 emoji 記進「明確不做」、任務 17 驗收 6 移除（編號不遞補）。選 (b)，就補上驗收 6 的測資與在裝置上的判讀方式。選 (c)，就另開一個任務改 §4.4，並重新核對 §4 整節。決策 M 移到附錄。

## 本輪（v3.19）我自己做的判斷（你可以否決，改起來成本都很小）

1. **抽屜截短的 bug 併進本規格處理，開成任務 17，不另開 slug。** 理由和 RD 轉交時說的一樣：正確行為由 §5.2 與「明確不做」那一條管，另開 slug 最後還是要回來改這份。
