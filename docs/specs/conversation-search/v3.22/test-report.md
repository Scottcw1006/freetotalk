  - §6.2：**並非每個非 ASCII 字元都會拋例外** —— U+00A0 送出時完全不報錯、欄位也完全不變（無聲失敗），比 U+3000 那個例外更容易被誤判成「送進去了」。
  - §6.4：長按空白鍵那一條補上**當場可跑的確認方式**（送同座標長按 1.5 秒 → 截圖看到「Change keyboard」對話框、逐碼位讀欄位一個字元都沒進去）。
  - §6.5：**2026-09-16 逐頁查過** —— 英文與注音兩個版面的主鍵盤、`?123` 第一頁、`=\<` 第二頁都沒有 U+3000 / U+00A0 的鍵，並寫明判準（鍵盤與 `input text` 兩條路都不通，就等於這個字元在這個環境產不出來）。
  - §9：**「按兩次返回」的批次特別容易把人送出 app** —— 第一次 BACK 若因為鍵盤其實沒開而直接退了一層，第二次就離開 app，接下來整批指令會安靜地打在桌面或別的 app 上而每一步都「成功」；建議優先用畫面上自己的返回控制項，並附確認方式。（本輪實際踩到兩次，一次落在桌面、一次落在行事曆。）
  - §12：**開始之前先把整個複本目錄刪掉重建** —— scratchpad 路徑可能與先前某一輪相同，裡面留著上一輪複製或改過的原始碼；同一個類別出現兩份時編譯器報的是看起來無關的 `overload resolution ambiguity`，**更糟的是它編得過、而你量到的是上一輪改過的那份**。附確認方式（`find` 只列出本輪放進去的檔 + 逐檔 `cmp` 專案原檔）。（本輪實際踩到。）
- **刪掉的越界內容**：**沒有**。逐句掃過全檔（grep 產品名、套件名、人格／模型名稱、產品文案），沒有任何一句不通過「換成完全不同的產品還成立嗎」這個判準 —— 文件裡出現的「抽屜／側邊面板」「覆蓋層」都是泛指的 UI 型態，不是這個產品的觀察。
- `docs/qa-tools/` 本輪**沒有新增或修改腳本**。`ui.py` 與 `hashdir.sh` 都跑過 selftest 才用。本輪寫的導覽 helper（開抽屜、進搜尋、捲動找列）是**這個產品的操作步驟**，通不過「換成完全不同的產品還成立嗎」，所以**刻意留在 scratchpad、沒有進 `docs/qa-tools/`**。
