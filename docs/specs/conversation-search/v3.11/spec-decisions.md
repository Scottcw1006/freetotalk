### 決策 H：資料夾版控之後，別的文件要怎麼指向這份 spec？

**這是新的目錄結構造成的，不是你交辦的四筆之一 —— 我是在核對 `docs/product/features.md` 需不需要更新時撞到的。**

**現況**：`docs/product/features.md` 有三十幾處寫著 `docs/specs/conversation-search/spec.md` §X 與 `docs/specs/stop-generation/spec.md` RX。**那兩個路徑現在都不存在了** —— 兩份 spec 都搬進了自己的版號目錄（`v3.10/`、`v3.11/`、`v3/`）。**這不是本輪造成的**（搬遷發生在更早），但本輪是第一次有人去追那些路徑。

**為什麼我不自己選一個修法**：
- 它**波及這個功能以外**：同一個問題在 `stop-generation` 那一輪一模一樣，而兩邊的做法必須一致，否則 `features.md` 裡會有兩種指法。**依「兩輪之間的衝突不得由 PM 自己選一邊」，這一題要你拍板，然後由我去同步兩邊的 spec。**
- 四個做法的長期成本差很多，而且差別落在**別人**身上（維護 `features.md` 的人、下一輪的 PM）。

| 選項 | 得到 | 代價 |
|---|---|---|
| **(a) `features.md` 改指版號目錄**（`…/v3.11/spec.md` §5.1） | 每一個引用都精確、追得到，而且指的是一份不會再變的定版 | **每一輪都要改那三十幾處**，而改它的人是 PM —— 這正是這份 spec 記過好幾次的那個失效模式（靠人記得同步的機械資訊會腐爛，而且腐爛時沒有人會發現） |
| **(b) slug 根目錄留一個不進版控的入口**（一個小檔，只寫「現行定版在哪個目錄」），`features.md` 改指 slug 目錄 + 節號 | 每一輪只要改一行；讀的人一定找得到現行版 | 多一個檔要維護（但只有一行）；「現行定版」與「上一輪定版」的差別要靠讀的人自己意識到 |
| **(c) `features.md` 只指 slug 目錄 + 節號**（不寫檔名與版號） | **零維護** —— 版號目錄怎麼長都不影響 | 讀的人多一步（自己挑最新的版號目錄）；而且它依賴「節號跨版本穩定」這個性質，目前成立（§5.1 從 v2 到現在沒動過），但沒有東西保證它 |
| **(d) 不處理** | 不花時間 | 那三十幾個引用**現在就是斷的**，而 `features.md` 的用途正是「從一個功能追到它的規格」 |

**我的傾向是 (c)**（零維護，而且它指的是**性質**不是**位置** —— 那正是你自己定下的引用紀律），**必要時配 (b) 當補強**。**但這是你的決定**，而且拍板之後 `stop-generation` 那邊要一起改。

**在你拍板之前**：`features.md` 我一個字都沒有動；`spec.md` 內部的跨檔引用不受影響（同目錄相對檔名，版號目錄怎麼搬都對）。
