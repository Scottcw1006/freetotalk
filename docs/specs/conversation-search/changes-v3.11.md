# 這一輪改了什麼

v3.10 → **v3.11**。**沒有新功能、沒有 bug、沒有改變任何一條規則要求的行為。**

起因是收件匣四筆，全部是使用者裁決：(1) 資料夾版控；(2) **架構決策 §A–§G 依准入判準重新分類、§F 整節收掉**；(3) **驗收條文的一次性全面掃描**（追溯不到使用者後果的移除或改寫）；(4) **任務 3 驗收 16 指定測資形狀**。第 2、3 筆使用者明講要同一輪做完。

**這一輪的改動幅度是這份 spec 至今最大的一次，但它動的是「規則寫在哪、誰負責驗」，不是「什麼算對」。** 產品該有的行為一個字都沒有變。

**入口檔仍是 `spec.md`**，五份檔案的分法沒有變。**新的路徑是 `docs/specs/conversation-search/v3.11/`** —— `v3.10/` 一個字都沒有動（含它底下的 `test-report.md`，那份報告屬於 v3.10，沒有複製也沒有搬走）。

**三件事 RD 與 QA 一定要先知道：**

1. **`spec-architecture.md` 整份變成建議，QA 不驗它。** RD 用了不一樣的做法而滿足行為規格與驗收 —— 那是開發完成，不是缺陷。
2. **`spec.md` 多了兩節**：**§2.11**（什麼算空白只能有一個答案）與 **§9**（對話存取層必須保留的既有行為）。**兩節的規則都是從架構決策原文搬過來的，一個字都沒有改。**
3. **很多驗收條文不見了，但沒有一條「要求」被放寬。** 每一個被移除的編號底下都留著一行，寫它原本守什麼、現在還有沒有東西在守。**編號一律保留不遞補。**

# 附加報告四：任務 3 驗收 16 為什麼要寫到測資這一層

**現象（QA 全驗 2026-09-10 + RD 複驗）**：這條指名的測試**零鑑別力**。把 `spec.md` §4.4 要求的兩處保護整個拿掉，全套單元測試仍然全綠。

**原因**：舊測資的形狀在數學上永遠碰不到邊界 —— 視窗尾端與 emoji 起點的距離恆為偶數，視窗起點又永遠落在 BMP 區間裡。**測試看起來在驗 §4.4，實際上什麼都沒驗。**

**本輪的處置**：
- **條文寫出兩個方向各自的測資性質**（起點方向：命中起點往前 20 個 code unit 那個位置要落在一對代理對的後半；尾端方向：視窗起點往後 60 個 code unit 那個位置要落在一對代理對的中間），**各附一個可用的形狀**。
- **兩支測試都要，而且要各自獨立**（只讓其中一側的保護失效時，只有對應的那一支變紅）—— **舊條文只指名一支，尾端那個方向從來沒有任何條文在守。**
- **加上正向對照**：片段裡必須仍然完整含有查詢詞，否則一個回傳空片段的實作也會通過。
- **刻意不指名測試方法的名字**：名字是隨時會被改的東西。

**RD 端已經做完並逐一突變驗證過**（只拿掉起點那側 → 只有第一支紅；只拿掉尾端那側 → 只有第二支紅；原始碼已還原）。**本輪只是把條文補上去。**

**它同時是任務 14 驗收 2 的第一個實例**：「對每一條說得出什麼樣的實作會讓它變紅」—— 這一條當初說不出來，而沒有人發現。
