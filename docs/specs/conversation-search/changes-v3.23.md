# 這一輪改了什麼

**沒有新功能、沒有 bug、沒有改動任何一條規則、沒有新增任何實作要求。行為規格 §1–§9 一個字都沒有動。** 處理收件匣一筆（[2026-09-16 14:45]，v3.22 全驗的 QA 打回、由 RD 轉交）：

**任務 8 驗收 14 磁碟那一半的判定基準換掉。** 舊措辭是「三者都不得在磁碟上新增或**改寫**任何對話檔」，而 `v3.23/spec.md` §8.2「不算一次更新」自己就明寫這些動作「在內部經過了『把對話寫回去』這條路」—— **寫檔本來就會發生**，§8.2 禁止的是時間前進；§8.4「可判定（儲存體裡的時間不動）」的建議判定方式也是比對**內容**。**舊措辭禁止的是一個機制動作，而規則要的是一個結果**，照字面判會把一個完全正確的實作判成 fail。

條文現在判的是：**操作前後沒有多出新的對話檔，每一段既有對話讀回來的內容也都相同**；**App 把某個檔重寫一次、而寫出來的內容相同，不算違反**。同時補上兩項前置條件與一段「這一條獨自抓得到什麼」。

**`spec-decisions.md` 維持 0 項待決**（為什麼這一題沒有升級成決策，寫在該檔「目前狀態（v3.23）」）。

# 未改動但與本輪改動互相牽動的章節

- **`v3.23/spec.md` §8.2「不算一次更新」與 §8.4「可判定（儲存體裡的時間不動）」**：本輪的改動是**條文去對齊這兩節**，兩節本身一個字都沒有動。改它們之前要回頭看任務 8 驗收 14。
- **`v3.23/spec.md` §9.1「儲存一段空白對話等於刪檔，不是寫檔」**：它規定的「沒有使用者訊息的既有對話檔被打開再離開就清掉」，是任務 8 驗收 14 新增第一項前置條件的理由。**那個行為是規格行為，不是驗收 14 的 fail。**
- **任務 13 驗收 2（§8.4 的實機判定）**：驗的性質與驗收 14 相同（切走之後存檔內容不變），但走的是**抽屜**入口。**兩條不重複** —— 搜尋命中列那個入口沒有別的條文在走。動其中一條之前看另一條。
- **任務 8 驗收 3、4、5、13**：驗收 14 的行為那一半與它們重疊，**那是使用者在 v3.10 單獨表過態保留的**，本輪沒有動這個安排。
- **`docs/qa-environment.md` §4「App 私有資料的快照與還原」底下的「已知的位元組層面陷阱」**：spec 只依賴「它記著怎麼避開手寫 JSON 與 App 序列化的位元組差異」這個性質，**不依賴它任何一句具體結論**。那份文件不是本規格維護的。
