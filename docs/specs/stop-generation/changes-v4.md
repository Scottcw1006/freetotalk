# 這一輪改了什麼

**起因**：收件匣裡三筆待處理 —— (1) `conversation-search` 的 PM 通知我們附錄裡有兩處指向他們的引用已經指不到了；(2) 使用者把驗收環境從 Pixel 9 實機改成 Android 模擬器，裁決轉給本規格處理條文字面；(3) **S2 拍板為 (B)**（過程條文不禁止，但要標明它驗不到什麼）。

**動到的方面**：跨文件與跨檔引用的寫法、條文裡對驗收裝置的字面預設、S2 的落位。**沒有任何一條規則的實質內容被改動，也沒有任何程式碼改動。**

**本輪的 spec 定版在 `v4/`。** v3 目錄一個字都沒有動（`diff -r v3 v4` 看得到本輪的全部差異）；`v3/test-report.md` 刻意沒有複製過去 —— 驗證報告留在它所驗的那一版。

> **這份文件是索引，不是規格。** 規則的原文只在 `v4/spec.md`，那裡才是唯一真相。下面只告訴你要做哪些、要去讀哪幾節。

# 這一輪要做的任務（完整清單）

**RD 這一輪沒有事情要做。QA 這一輪要不要做事，取決於使用者怎麼決定 S3。** 下面把 `spec.md` 的五個任務逐條走過一遍 —— 這一節不是「有沒有被改過」的清單，是「這一輪要不要做」的清單。

- **任務 1** 把「留下什麼」收到一個地方，並讓它能被 JVM 測試直接呼叫　〔**本輪無需再做**；已實作並通過全部五條驗收。**條文未變**〕
- **任務 2** 使用者停止不再走錯誤那條路，且停止後狀態收斂　〔**實作本輪無需再做**；**驗收 6 的措辭改了**（「實機不強制重現」→「在裝置上不強制重現」），判定結果不變。**若使用者選了 S3 的 (B) 或 (C)，這個任務的裝置端驗收要在模擬器上重跑**〕
- **任務 3** 停止那一次必須落盤，而且寫的是被停止的那一段　〔**實作本輪無需再做**；條文只改了 `findings.md` 的相對路徑。**S3 選 (B) 時要重跑**〕
- **任務 4** 回歸驗證　〔**這一條平常是「每輪必做」，這一輪不是**：本輪沒有任何程式碼、建置或規則的實質改動，回歸驗證沒有對象。**只要下一輪動到任何一行程式，它就立刻恢復成必做。** 驗收 6 補上了對方的節名，判定內容不變。**S3 選 (B) 時要重跑**〕
- **任務 5** 更新架構文件　〔**本輪無需再做，而且 `plan/architecture.html` 本輪一個字都沒有被動過**。核對結論寫在任務 5 的第一行：沒有程式碼改動、換驗收環境也不影響那份文件（它唯一提到裝置的地方是頁尾的效能量測環境標註，那是歷史標註）〕

**這一輪唯一在等人的東西是 `v4/spec-decisions.md` 的 S3，而它等的是使用者，不是 RD 或 QA。** 不決定它，這一輪照樣是完成的狀態。

# 本輪移除或失效的任務／驗收

**沒有任何一條驗收被移除或失效。** 五個任務的每一條驗收都維持原本要求的性質，判定方式一個字都沒有放寬。

**特別點名一條容易被誤讀成「鬆綁」的**：R1–R11 的共同前置從「在回覆開始串流後 **3–5 秒內**按下停止」改成「**在那則回覆已經顯示出至少一個字、而且還沒有自然結束的時候**按下停止」。**這是把一個預設了生成速度的秒數換成它真正要的狀態**，不是放寬 —— 舊寫法在一台生成較慢的裝置上可能根本產不出「已經有文字」這個情境，新寫法則不論裝置快慢都產得出來。
