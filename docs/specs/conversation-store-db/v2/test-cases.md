## 裝置（emulator-5554；使用者已同意清空 App 資料，模型檔保留）

情境 S0：從工作區建置並覆蓋安裝；force-stop；只刪使用者資料（databases/、shared_prefs/、files/conversations/），保留 files/*.task；記下已解壓的模型。

情境 A：升級（乾淨起點，第二條路造前置）
前置：App 停止；照 `git show a4c7b20:app/src/main/java/com/example/demo/data/ConversationStore.kt` 的格式造三個舊檔（各含一個獨特英文詞）放進 files/conversations/；session 偏好寫入其中一個的 id、非預設人格、非預設且已解壓的模型；記下 files/ 清單與大小。
- A1 冷啟動後一次 dump＋截圖＋ls
  → 任務 4 驗收 2 (i)「抽屜顯示「還沒有其他對話。」；搜尋那三段裡的詞都找不到」
  → (ii)「聊天畫面是一段只有開場白的新對話，頂端的人格與模型是寫進偏好的那一組」
  → (iii)「舊位置不存在」
  → (iv)「沒有出現「正在把 AI 模型解壓到裝置上」的橫幅，App 檔案目錄裡原有的模型檔仍在（以檔案清單與大小判定）」
- A2 送出一則訊息、等回覆結束、不做任何事、force-stop、冷啟動
  → 任務 4 驗收 2 (v)「續接到那段、內容都在、舊位置仍不存在」
  → 任務 7 驗收 8 前半「續接到那段，使用者那句與完整回覆都在」（同時是 §1.1 的裝置端可判定）
  → 任務 7 驗收 10 的「送出」「串流」「冷啟動續接」
- A3 換人格產生沒說過話的對話 → force-stop → 冷啟動
  → 任務 7 驗收 8 後半「以記住的人格與模型開新的一段」
  → 任務 7 驗收 10 的「切換人格」

情境 H：搜尋來源
- H1 在一段有內容的對話換人格，得到只有開場白的 N → 進搜尋查 N 開場白裡的一個詞
  → 任務 3 驗收 1「N 的分組出現，而且排在最前」
- H2 新對話送出含 `harborlight` 的長回覆提示，回覆生成中進搜尋查 `harborlight`
  → 任務 3 驗收 2「那段的分組出現。之後回到聊天，確認那則回覆結尾是中斷標記（進入搜尋不會停止生成時，改以「進入搜尋當下回覆還在增加」的截圖為證）」

情境 B：串流中切換（任務 2 驗收 3，每一次開一段新的 A，提示 `Write a very long detailed story about the sea, at least 600 words`，Gemma3 1B 起步）
每次共同的預期（原文 §2.2）：「1. 清單裡有 A，恰好一列，而且是第一列；2. 關上抽屜、不做任何其他動作、等 10 秒再打開 → A 仍在、仍是一列、仍是第一列；3. 從抽屜進入搜尋，查 `sea` → A 的分組出現；4. 從抽屜打開 A → 那則回覆留下切換當下已經顯示的文字，結尾是中斷標記」；「算不算數」看 A 的回覆結尾是中斷標記。
- B1 入口：切換人格 → 預期 1–4（另記 §2.2 與任務 7 驗收 10 的「串流時回覆逐步增加」以連續截圖為證）
- B2 入口：切換模型 → 預期 1–4（任務 7 驗收 10 的「切換模型」）
- B3 入口：開始新的對話 → 預期 1–4
- B4 入口：開啟另一段對話 B（B＝既有對話）。切換前讀 DB 當基準，觀察後再讀 DB
  → 預期 1–4 與 5「B 是開著的那段，B 不在清單上」
  → 任務 7 驗收 2「儲存裡 A 那段的那則回覆以中斷標記結尾；B 在儲存裡的內容（每一個欄位、每一則訊息）與切換前相同」
- B5 零文字變體（切換人格，回覆還沒出現任何一個字時）
  → 「那則空回覆不留下，使用者剛送出的那句留著」→ 預期 1–3

情境 C：停止後立刻結束行程
- C1 生成中按停止 → dump 回覆文字 → 立刻 force-stop → 冷啟動
  → 任務 7 驗收 1「續接到那段，那則回覆的文字與停止時相同、以中斷標記結尾」
  → 任務 7 驗收 10 的「停止後回覆不再增加」

情境 I：從 App 以外讀得出來
- I1 正常操作建立兩段對話（其中一段含 emoji 與換行）→ 讀 DB 列出每一列每個欄位與每則訊息 → 與畫面比對 → 判讀完從 App 刪掉那兩段
  → 任務 6 驗收 1「列出的結果與 App 畫面上看得到的一致」

情境 P：切走沒改的、刪除（讀 DB 基準 → 冷啟動 → 操作 → 讀 DB）
前置：至少三段有內容的對話，續接的那段 X 最後更新時間早於現在 1 分鐘以上。
- P1 冷啟動續接 X，不做任何事，從抽屜開 Y；接著（開著 Y）從抽屜刪 Z；force-stop 讀 DB；冷啟動，抽屜與搜尋找 Z
  → 任務 7 驗收 3「儲存裡 A（＝X）的內容（含最後更新時間）與切換前相同」
  → 任務 7 驗收 7「儲存裡少一段、沒有 B（＝Z）、A（＝Y）的內容不變；冷啟動後抽屜與搜尋都找不到 B」

情境 E：同一次執行裡的清單更新（任務 2 驗收 4）
- E1 不在生成時從抽屜開另一段 → 開抽屜；刪清單上的一段 → 不關抽屜直接 dump；新對話送出、等回覆結束、切走 → 開抽屜
  → 「剛才那段在」「那一列立刻消失，不必關再開」「那段在，預覽是完整回覆的開頭」
  → 任務 7 驗收 10 的「刪除後那一列消失」

情境 F：空白對話不留（任務 7 驗收 4）
- F1 讀 DB 基準 R0；各以換人格產生只有開場白的對話，分別用 開另一段／開始新的對話／換人格／換模型 離開，每一次之後 force-stop 讀 DB
  → 「每一次前後，儲存裡的對話數與每一段的內容都相同」
- F2 正向對照：新對話送出訊息、等回覆結束、離開，讀 DB
  → 「儲存裡多了那一段」

情境 G：搜尋不改動儲存
- G1 前置擺設完成後讀 DB 基準 → 冷啟動 → 進搜尋打字到有結果 → 點另一段的命中列 → 再進搜尋點回原本那段 → force-stop 讀 DB
  → 任務 7 驗收 9「儲存裡的對話數與每一段的內容都與基準相同」

情境 X：外面寫入只含助理訊息的對話
- X1 正常操作建立含使用者訊息的 Y 並切走 → force-stop → 從 App 以外寫入只含助理訊息的 X → 冷啟動 → 看抽屜 → 點 X → 從抽屜開 Y → force-stop 讀 DB → 冷啟動看抽屜與搜尋 → 開始新的對話 → force-stop 讀 DB → 清理 Y
  → 任務 6 驗收 2「冷啟動後 X 出現在抽屜上，標題是「還沒說話」，點開看得到那幾則助理訊息」
  → 任務 7 驗收 5「儲存裡沒有 X、冷啟動後抽屜與搜尋都找不到 X；再開一段新的對話 → 儲存裡 Y 仍在、內容不變」

情境 K：一段讀不起來（儲存裡恰好三段，App 做得出來的兩段用正常操作建立）
- K1 force-stop → 從 App 以外讓其中一段的 messages 解不開 → 冷啟動 → dump 抽屜、搜尋
  → 任務 7 驗收 6「冷啟動後抽屜列出那兩段，App 不閃退」
  → 任務 6 驗收 3 前半「讓儲存裡一段對話解不開（其餘照常，冷啟動後其餘都在清單上）」

情境 M：寫不進去（盡力）
- M1 正常操作存好 P → force-stop → 讓儲存唯讀 → 冷啟動 → 另一段對話送出、等回覆結束（並切走觸發存檔）→ 觀察 → 恢復可寫 → 送出一則並等回覆結束 → 冷啟動
  → 任務 5 驗收 2「不閃退；出現「有一段對話沒能存下來。」且至少停留 3 秒；那段內容仍在畫面上、可以再送出；P 仍在抽屜上、內容不變。恢復可寫之後再送出一則並等回覆結束 → 冷啟動後那段在」

情境 L：整份壞掉（最後做）
- L1 正常操作存好 P（含獨特詞）→ 記偏好內容 → force-stop → 覆寫 conversations.db 成亂碼、刪 -wal/-shm → 冷啟動 → 連續觀察提示 → 抽屜、搜尋 P 的詞 → 讀偏好 → 送出並收到回覆、再送出並按停止 → 新對話送出、等回覆結束 → force-stop → 冷啟動
  → 任務 5 驗收 1「不閃退；聊天畫面出現；沒有出現解壓橫幅；可以送出訊息、收到回覆、按停止」「畫面上出現一次「之前的對話紀錄讀不出來，已經清空，從這裡重新開始。」，至少停留 3 秒或直到關掉它」「抽屜是「還沒有其他對話。」、搜尋 P 裡的詞找不到」「「上次停在哪」的偏好內容與冷啟動前相同」「在一段新對話送出訊息、等回覆結束、再冷啟動 → 那段在，而且提示不再出現」
  → 任務 6 驗收 3 後半「讓整份儲存讀不起來（冷啟動後走 spec.md §5.1）」
