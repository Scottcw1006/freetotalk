## 本輪（v4）我自己做的判斷（不擋工，你可以推翻）

1. **從抽屜刪除一段對話、而刪除失敗時，這一輪不規定要提示**（列進「明確不做」並附觸發條件）。RD 轉述 QA 看到的現況：不閃退、不提示、那一列還在。
   - **為什麼不規定**：
     - 使用者後果不大：看到的是「按了刪除沒反應」，資料沒有少，也不會誤以為已經刪掉；
     - **規定了也沒有人驗得到**：模擬器上造不出「清單上有列、刪除卻失敗」的時機（開不起來時清單上沒有列；App 執行中改檔案權限，已經開著的資料庫不受影響），而負責提示的那一層在不經過裝置的測試裡建不起來（T1 不在本輪）。寫下去會是一條沒有任何驗收守著的規則。
   - **你要改成「規定」的話**：會多一句提示（比照「有一段對話沒能存下來。」，例如「這段對話沒能刪除。」）、RD 要改刪除的收尾，而這條規則要嘛接受沒有驗收，要嘛先做 T1。
2. **`b0ad0fa` 不算 `stop-generation` 重驗的第三次觸發**，沒有拿來請你裁決。理由見上面「跨輪分辨過」。你若認為 v3 裁決之後任何一次程式改動都該問你，告訴我，之後每輪都會列出來。
3. **「測資不得等於退回值」寫成全部條文的通則**，不只改 QA 點名的任務 1 驗收 1。套到的另外兩處：任務 1 驗收 3（E 那一段的內容相等）、任務 7 驗收 8（裝置上冷啟動回到上次那段，這一輪起也要比人格與模型）。QA 在 v3 已經用了非預設值，這兩處主要是把它寫死。
4. **順手處理了 QA 報告裡另外兩點觀察**（收件匣沒有逐條轉，報告原文有）：
   - 任務 3 驗收 2（回覆生成中搜尋）的「算不算數」改成：看到搜尋結果後立刻回到聊天，**回覆仍在生成才算**。v3 用的「進入搜尋前的截圖」證明不了查詢那一刻還在生成。**這一條比 v3 嚴**，模型或提示可能要換成生成較久的。
